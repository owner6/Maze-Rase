# Покрокова інструкція: генерація референсів для арт-біблії

Час: 3–5 годин чистої роботи. Результат: 20–40 зображень у `moodboard/`,
3 у `lighting/`, заповнена палітра в `README.md`.
Промпти беруться з `prompts.md`, номери нижче збігаються з ним.

## Крок 0. Підготовка (15 хв)

1. Обрати інструмент. Рекомендація:
   - **Midjourney v6** (платно, ~$10): найкраща консистентність через `--sref`, найпростіше.
   - **Flux.1 dev** локально через ComfyUI / Forge: безплатно, потрібна GPU ≥ 12 ГБ VRAM.
   - **Leonardo.ai / Ideogram**: безплатний ліміт на день, підійде для проби.
   - DALL-E / ChatGPT: слабший у фотореалізмі бункерів, брати лише як запасний.
2. Створити робочу папку поза репозиторієм (наприклад `~/gen/bunker71/`).
   У git кладемо тільки відібране, а не всі 200 варіантів.
3. Відкрити `prompts.md` і скопіювати PREFIX та SUFFIX у нотатки: вони
   вставляються в кожен промпт.
4. Завести файл `~/gen/bunker71/log.md`: номер промпту, seed, що змінив, вердикт.

## Крок 1. Еталон стилю (45 хв). Найважливіший крок

Мета: одна картинка коридору, яка стане «якорем» для всіх інших.

1. Згенерувати **01_corridor_straight**, 4 варіанти, 2–3 рази з різними seed.
2. Оцінити за чеклістом еталона:
   - [ ] Видно стики панелей і рейку під стелею (головна фішка світу).
   - [ ] Масштаб «читається»: коридор виглядає на 4 м ширини, не тунель і не ангар.
   - [ ] Дорого, але зношено. Не стерильний sci-fi, не руїна.
   - [ ] Палітра: сірий, бежевий, темна сталь, трохи іржі. Без неону.
   - [ ] Немає вікон, людей, тексту.
3. Якщо жоден не проходить, правити **по одному слову за раз**: додати
   `beige composite panels` якщо занадто металево, `worn, dusty` якщо
   занадто чисто, `narrow` якщо завеликий масштаб.
4. Обраний кадр зберегти як `moodboard/01_corridor_straight.jpg` і зафіксувати:
   - Midjourney: скопіювати URL картинки, далі всюди додавати `--sref <url> --sw 60`.
   - Flux/SD: записати seed і використати IP-Adapter з цією картинкою (вага 0.5).
5. Погодити еталон із командою до наступного кроку. Переробляти після
   40 картинок дорого.

## Крок 2. Панель і решта коридорів (30 хв)

Промпти 02, 03, 04, 24. По 4 варіанти кожен, з `--sref` еталона.

- 04_panel_closeup генерувати з `--ar 1:1` замість 16:9, це макро.
- Якщо панелі виглядають щоразу по-різному, це нормально: художник
  потім обере одну конструкцію. Але зафіксувати обрану в README, розділ 5.

## Крок 3. Реальні бункери (30 хв)

Промпти 05–08. Тут `--sref` **не** використовувати: мета показати
реальність, а не наш стиль. Це референси матеріалів і атмосфери.

Альтернатива швидша за генерацію: пошук фото.
Запити: `Swiss civil protection shelter interior`, `бомбосховище інтерʼєр`,
`Survival Condo Kansas interior`, `Bunker 42 Moscow corridor`. Ліцензія
не важлива, у гру ці фото не потрапляють.

## Крок 4. Кімнати MVP (60–90 хв)

Промпти 09–16, з `--sref` еталона. Це найдовший крок.

Порядок: стартовий бокс → сейф-кімната → спальня → кухня → склад →
медпункт → торговий пост → кімната керування. Перші дві найважливіші
для геймплею (безпечні зони), їм більше ітерацій.

На кожну кімнату:
1. 4 варіанти з базовим промптом.
2. Перевірити: **чи впізнається тип кімнати без підпису?** Показати
   картинку колезі на 3 секунди і спитати «що це за кімната». Якщо не
   вгадує, посилити ключовий обʼєкт у промпті (`large industrial fridge
   in the center` тощо).
3. Перевірити розмір: кімната має вміщатися в 2 × 2 … 4 × 3 клітинки
   (8 × 8 … 16 × 12 м). Якщо генератор малює бальну залу, додати `small`,
   `cramped`, `8 by 8 meter room`.
4. Лишити 1–2 варіанти.

Типові проблеми і фікси:

| Проблема | Фікс у промпті |
|---|---|
| Занадто чисто, як реклама | `worn, dusty, three weeks abandoned, scuffed` |
| Вікна або денне світло | у негатив: `windows, daylight, sunlight` |
| Люди в кадрі | `empty room, no people` на початок промпту |
| Неон, кіберпанк | у негатив: `neon, cyberpunk, blue glow` |
| Різна висота стелі | `3.2 meter ceiling, low ceiling` |
| Текст-каша на стінах | `no text, no signs` або лишити, потім замалювати |

## Крок 5. Знос, стеля, вентиляція (30 хв)

Промпти 17–23. З `--sref` для 18, 19, 22, 24; без нього для макро 17, 20
і для схеми 23 (там інший стиль: креслення).

Для 21_vent_shaft_interior зробити додатково варіант `--ar 9:16`:
вертикальний кадр краще передає тісноту шахти.

## Крок 6. Освітлення (30 хв)

Три промпти з розділу «Освітлення». Мета: одна кімната, три стани.

1. Спочатку **lighting/01_day**. Домогтися чистої читабельної спальні.
2. Зафіксувати її: у Midjourney `--cref` не підходить для інтерʼєрів,
   тому використати `--sref <url 01_day> --sw 100` плюс той самий seed
   (`--seed N`). У ComfyUI: той самий seed + ControlNet depth від 01_day.
3. Згенерувати 02 і 03, змінюючи в промпті **лише** опис світла.
4. Перевірити поруч усі три: геометрія має бути майже однакова, світло
   різне. Якщо геометрія «поїхала», підняти `--sw` або вагу ControlNet.
5. Під кожним записати в `lighting/README.md` 3–5 рядків: колір джерела,
   де стоїть, що в тіні, який настрій.

## Крок 7. Палітра (20 хв)

1. Обрати 6–8 найкращих зображень мудборду (обовʼязково еталон коридору,
   сейф-кімнату, аварійне освітлення).
2. Завантажити в Adobe Color → Extract Theme або coolors.co → Image picker.
3. Вписати HEX у таблицю `README.md`, розділ 3. Для ролей «безпека»,
   «небезпека», «вихід» кольори можна взяти не з картинок, а призначити
   свідомо: вони мають відрізнятися для дальтоніків. Перевірити на
   https://www.color-blindness.com/coblis-color-blindness-simulator/.

## Крок 8. Відбір і збереження (20 хв)

1. Перейменувати обрані файли за схемою `NN_категорія_опис.jpg` з `prompts.md`.
2. Формати: фотореалістичні референси (мудборд, освітлення) у **JPEG**
   якість 85; схема рейок (23), палітра і контактний лист у **PNG**
   (чіткі лінії й текст). WebP не використовувати: Figma/Miro відкривають
   гірше. Генератори віддають PNG, конвертувати і зменшити до 1920 px
   по довгій стороні одним рядком (ImageMagick):
   ```
   mogrify -format jpg -resize 1920x1920\> -quality 85 *.png
   ```
   Оригінальні PNG лишити в `~/gen/bunker71/`, у репозиторій не класти.
   Папка на 30 картинок має важити до ~15 МБ, інакше Git LFS.
3. Скласти в `docs/art-bible/moodboard/` і `lighting/`.
4. У `moodboard/README.md` дописати таблицю: файл, інструмент, seed,
   фінальний промпт якщо відрізняється від `prompts.md`.
5. Зібрати контактний лист (усі картинки на одному аркуші) для перегляду
   командою:
   ```
   montage moodboard/*.jpg -tile 6x -geometry 320x180+4+4 contact_sheet.jpg
   ```
6. Пройти чекліст готовності в `README.md` і закрити ST-01.3 (частину
   «арт-біблія») через PR.

## Що НЕ робити

- Не генерувати всі 27 промптів за один прохід без еталона: вийде
  27 різних стилів.
- Не правити в промпті кілька речей одночасно: не зрозумієш, що спрацювало.
- Не класти в репозиторій сотні відбракованих варіантів.
- Не використовувати ці картинки як текстури в грі: це референси для
  художника, ліцензія генераторів на ігрові асети окреме питання.
